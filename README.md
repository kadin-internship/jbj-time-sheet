# JBJ Time Sheet

Internal time tracking app for JBJ: employees log hours against projects, admins
manage employees/projects/PTO/meetings and export timesheets as PDF, Excel, and
CSV. Built with Next.js 16 (App Router), TypeScript, Tailwind CSS, Drizzle ORM,
and Neon Postgres. Hosted on Vercel.

## Live app

- Production: https://jbj-time-sheet.vercel.app
- Vercel project: `jbj-time-sheet` (team `jbj1`)
- GitHub: https://github.com/kadin-internship/jbj-time-sheet

## Important: dev and production share one database

`DATABASE_URL` in `.env.local` points at the **same** Neon Postgres database
used by the live production deployment — there is no separate staging/dev
database. Anything you create, edit, or delete while running locally (`npm run
dev`) happens live, immediately, for real users. Be careful with test data and
scripts that write to the database; clean up anything you create.

## Getting started

```bash
npm install
npm run dev
```

Open http://localhost:3000 (or whatever port is free). You'll need a
`.env.local` file (see below) — ask whoever currently holds credentials for
the values, or provision a new Neon database if starting fresh.

## Environment variables

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Neon Postgres connection string (shared dev/prod — see above) |
| `AUTH_SECRET` | Auth.js session signing secret |
| `CRON_SECRET` | Shared secret Vercel Cron sends as a Bearer token to authorize `/api/cron/backup` |
| `BLOB_READ_WRITE_TOKEN` | Auto-populated when a Vercel Blob store is created and connected to this project (Vercel dashboard → Storage). Required for the scheduled DB backup. |

`VERCEL_OIDC_TOKEN` in `.env.local` is auto-generated by the Vercel CLI when
the project is linked (`vercel link`) — you don't need to set it by hand.

## Database schema changes

`drizzle-kit push` has a recurring false-positive bug on this project where it
re-prompts to drop/recreate a constraint that already exists, which is risky
against a database with real data. For any additive schema change (new
column, new table), prefer applying it via a short one-off script using
`@neondatabase/serverless`'s `Pool` with raw SQL (`ALTER TABLE ... ADD COLUMN
IF NOT EXISTS ...`), rather than running `db:push` directly against
production. Only reach for `drizzle-kit generate`/`migrate` if a change is
genuinely destructive (rename, type change, dropping a column).

## Seed / test accounts

- `admin` / role: admin
- `employee` / role: employee ("Sample Employee")

Real accounts are created from `/admin/employees` — admins can create either
role from that page (there's a Role dropdown on the "Add Employee" form).
New accounts get a generated temporary password shown once to the admin, and
the new user is forced to set their own password on first login.

## Security features

- **Forced password change on first login** — any account created or
  password-reset by an admin must set a new password before using the app
  (enforced in `middleware.ts` via `session.user.mustChangePassword`).
- **Login rate limiting** — 5 failed attempts locks the account for 15
  minutes (`lib/db/queries/users.ts`, enforced in `lib/auth.ts`).
- **Security headers** — CSP, `X-Frame-Options`, HSTS, and related headers
  are set in `next.config.ts`.
- **Role checks** — every admin-only Server Action calls the shared
  `requireAdmin()` guard from `lib/auth/guards.ts`. `middleware.ts` also
  gates `/admin/*` pages, but only for GET requests (Server Actions are POST
  and must check auth themselves — this is intentional, see the comment in
  `middleware.ts`).
- **Excel import validation** — uploaded files are restricted to `.xlsx`/
  `.xlsm` and a 10 MB size cap before being parsed (`app/admin/import/actions.ts`).

## Scheduled database backup

`app/api/cron/backup/route.ts` dumps every table to JSON and uploads it as a
private Vercel Blob (`backups/YYYY-MM-DD.json`), triggered daily by the cron
schedule in `vercel.json`. It only runs (and only accepts requests) with a
valid `CRON_SECRET` — Vercel sets this automatically as the request's Bearer
token when it calls the route on schedule.

**One-time setup required before this runs in production:**
1. In the Vercel dashboard, go to the project's Storage tab and create a Blob
   store, connecting it to this project — this auto-populates
   `BLOB_READ_WRITE_TOKEN` in the project's environment variables.
2. Add `CRON_SECRET` to the project's environment variables in Vercel,
   matching the value in `.env.local`.

Until both are set, the cron job will run on schedule but fail at the auth
check or the upload step.

## Google Drive export (planned, not yet built)

There's an agreed design for exporting weekly timesheet PDFs automatically
into a per-employee folder structure in the company's shared Google Drive
(weekly, via a scheduled job, no manual step). Not implemented yet — ask
whoever's continuing this project whether it's still wanted before building
it, since it requires a Google Cloud service account to be added as a
collaborator on the relevant Drive folder.

## Deploying

Pushes to `main` on GitHub auto-deploy via Vercel's GitHub integration. To
deploy manually from this directory: `npx vercel --prod` (requires the
project to be linked — see `.vercel/project.json`).
